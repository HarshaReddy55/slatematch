# Implementation Guide

SlateMatch product pack, document 4 of 8. Previous: Architecture and System Design. Next: Deployment Guide.

## 4.1 Module-by-Module Code Map

### Backend Modules (`slatematch/backend/app/`)
* **`api.py`:** Defines all FastAPI routes, session middleware (`X-Workspace-Session`), Pydantic validation models for policy and inline ledger edits, atomic approval handlers, and diagnostics endpoints.
* **`domain.py`:** The core dataclasses every module shares: `Invoice`, `Payment`, `Policy` (with its validated defaults), `MatchLine`, and `MatchResult` - all money in integer cents.
* **`batch.py`:** Implements the six-agent pipeline, evidence-priority payment sorting, single-customer and currency filtering, auto-post settlement transactions, and per-agent timing telemetry.
* **`solvers.py`:** Implements `solve_milp` (the primary solver) and `solve_greedy` (the permanent evaluation baseline), tries the Rust kernel first on plain payments, counts distinct exact subsets for the ambiguity rule, re-verifies every returned set in exact integer cents with cuts and bounded retries, and records each result's objective terms and confidence derivation. The why-not counterfactual (`why_not_invoice`) forces an excluded invoice in and re-solves on demand; it runs only from the API, never inside the batch path.
* **`rust_bridge.py`:** Invokes the compiled `slatematch-kernel` binary over stdio with a JSON payload (`best_subset_rust`); `best_subset_py` is the reference implementation the 203-case equivalence suite compares it against. When the binary is absent the MILP decides, and the diagnostics view states which mode the system is in.
* **`reference_engine.py`:** The builder's original standalone engine (its own `solve_milp_reconciliation`), preserved in the tree for reference; it is not part of the run path. Reference extraction lives in `ingestion.py` and OCR repair in `fuzzy.py`.
* **`fuzzy.py`:** Computes Jaro-Winkler string similarity, resolves learned payer aliases from the workspace `aliases` table, and generates the OCR confusion variants (0/O, 1/I, 5/S, 8/B) behind the `ocr_reference` rung.
* **`anomaly.py`:** Computes deduction z-scores against the payer's own judged claim history in this workspace (the history is assembled in `batch.py`; below 3 samples a labelled baseline prior of $1,000 mean / $400 spread applies), classifies claims into the reason-code taxonomy, and fingerprints payments for duplicate detection.
* **`erp_sap.py`:** Constructs SAP S/4HANA `BAPI_ACC_DOCUMENT_POST` JSON payloads and ASC 606 / IFRS 15 EBRR reserve schedules.
* **`mail.py`:** Owns mail configuration, the send path with its `recorded_not_sent` honesty state, and the settlement and reminder draft builders. The four-stream hub itself is assembled in `api.py` from active run records, with dispute and chase draft text generated by `briefing.py`. The hub's four streams:
  1. Short-Pay and Unearned Discount Dispute Claims (with carrier POD citations, asserted only when the record shows a clean proof of delivery).
  2. Unidentified Wire / Exception Remittance Inquiries (for `NO_MATCH` and duplicate wires).
  3. SAP Settlement Confirmations (for `AUTO_POSTED` and `APPROVED` matches).
  4. Overdue Dunning Reminders (for unpaid open invoices remaining after reconciliation).
* **`forecast.py` & `ml.py`:** Computes an 8-week Monte Carlo cash forecast (P10/P50/P90) across the post-reconciliation residual ledger and ranks collector outreach by expected value using the validated payment delay model (MAE 2.95 days against a 7.67-day naive baseline, AUC 0.846; the trainer accepts real history rows, and until a real feed is wired it trains on a disclosed synthetic generator).
* **`ingestion.py`:** Fingerprints CSV column layouts, maps header synonyms (`inv_no`, `bill_no`, `doc_id`, `remit_text`), normalizes locale numbers, validates discount percentages (0% to 50%), and quarantines negative or malformed rows with reasons.
* **`ai.py`, `briefing.py`, `copilot.py`:** Manages Gemini API extraction with source-text amount verification, deterministic fallback parsing, executive run summaries, and workspace-grounded Q&A.
* **`repository.py` & `tenants.py`:** Manages SQLite `WAL` connections (`busy_timeout = 5000`), atomic compare-and-set match updates, partial-application records, and the audit trail with SHA-256 content fingerprints; `tenants.py` stores tenants and hashed API keys. The LRU session cache (128 sessions) lives in `api.py`.
* **`seed.py`:** The flagship demo case data: 19 invoices and 16 payments across 9 customers.
* **`scenarios.py`:** The ten scenario packs and their runner support, behind the scenario endpoints and the all-packs test.
* **`methodology.py`:** The methodology and JD-mapping content served at `GET /api/v1/methodology`.

### Frontend Modules (`slatematch/frontend/`)
* **`index.html` & `css/livecube.css`:** Defines the top workspace bar, the horizontal navigation bar across all 14 views, slide-over drawers, shimmer skeletons, and dark-mode enterprise styling.
* **`js/state.js`:** Manages client session UUIDs, API fetch wrappers, lazy tab rendering, and centralized workspace state synchronization.
* **`js/operate.js`:** Renders `02 Use Cases` and the `04 Run Reconciliation` pipeline (agent steps, stored-run rendering, run grading), plus the Dashboard's refresh and grading helpers.
* **`js/insight.js`:** Renders views `05 SAP BAPI & EBRR`, `06 Ledger` (with inline cell editing), `07 Forecast and Collections`, `10 Evaluations`, `11 Agent Health`, the `13 Architecture` diagnostics, and the product docs drawer that renders this pack in-product.
* **`js/assist.js`:** Holds the view-loader registry and renders `08 Outbound Mail Hub`, `09 Policy Studio` (with scratch-copy simulation preview), `12 Methodology`, the approvals queue and audit views, and the floating workspace Copilot. View `14 Product Thinking` is static markup with no loader.

## 4.2 Key API Contracts

| HTTP Method & Path | Purpose | Key Behavior & Guarantees |
| :--- | :--- | :--- |
| `GET /api/v1/workspace` | Hydrate active session state | Returns staged/settled invoices, payments, active policy, and latest run summary. |
| `POST /api/v1/cases/{cid}/load` | Stage a benchmark or demo case | Resets session tables and loads raw invoices and payments in `STAGED` state without pre-solving. |
| `POST /api/v1/batches` | Execute 6-agent reconciliation | Runs the payments supplied in the request body under the tenant's stored policy (an inline policy in the body is ignored by design), settles `AUTO_POSTED` invoices atomically, and returns agent timings and matches. The staged-workspace runner is `POST /api/v1/workspace/run`. |
| `POST /api/v1/matches/{match_id}/decision` | Maker-Checker approval or rejection | Body: {decision: approve or reject}. Atomic compare-and-set transition out of `PROPOSED` (a second concurrent decision gets a conflict); settles invoices in full, or reduces the open balance on a partial payment and records the partial application; saves the learned alias; issues the SAP `DZ` document number. |
| `GET /api/v1/approvals` | The Maker-Checker queue | Current `PROPOSED` matches, newest first - including the zero-line `NO_MATCH` refusal, by design. Approving the refusal (via the decision route above) books it to Unapplied Cash Suspense (GL 119900) as `PARKED_SUSPENSE` with an audit entry, and creates no AR posting. |
| `PUT /api/v1/policy` | Update governance thresholds | Validates threshold ranges and records before/after values in the audit trail. |
| `POST /api/v1/policy/preview` | Scratch-copy policy simulation | Clones workspace in memory and returns exact match shifts without mutating live session data. |

## 4.3 Verification and Automated Test Suite
The `backend/tests/` directory contains 134 automated tests across 29 `pytest` modules covering unit, integration, security, and UI contract checks:
```bash
python -m pytest backend/tests -q
```
Key test suites include:
* `test_audit_remediation.py`: Verifies idempotent re-runs, no double-posting, cross-customer/currency blocks, ambiguous tie detection, compare-and-set approval semantics, discount parsing, and the inline-handler interpolation scan.
* `test_milp_solvers.py` & `test_rust_equivalence.py`: Verifies exact cent equivalence between the Rust subset-sum kernel and its Python reference implementation across 203 cases, and grades `solve_milp` against the `solve_greedy` baseline.
* `test_erp_documents.py`: Verifies that every generated SAP S/4HANA `BAPI_ACC_DOCUMENT_POST` document balances debits and credits to 0 cents. (The resolved `CUSTOMER` and deterministic document-number assertions live in `test_audit_remediation.py`.)
* `test_refusal_parking.py`: Verifies that a `NO_MATCH` wire can never be approved into AR - approving its refusal parks it in suspense, and the only other route is a buyer inquiry.
